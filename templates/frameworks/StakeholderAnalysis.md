# 利益相关方分析(Stakeholder Analysis)框架

> 政策/项目/企业决策的多方力量地图 · 智库顾问标准模板 · v1.0 · 2026-09-11
> 适配:政策推演 / 重大项目立项 / ESG 与 CSR 评估 / 战略推演 / 利益冲突识别

---

## 1. 框架定位

**利益相关方分析** = 系统识别**决策影响 / 受决策影响**的**所有主体** → 评估其**权力、利益、立场、关系** → 制定**沟通、联盟、化解、监控**策略。
**提出者**:R. Edward Freeman(《Strategic Management: A Stakeholder Approach》,1984),从公司治理延展到公共政策与项目评估。
**用途**:当一个决策/项目/政策的**成败取决于多方博弈**时(不是单点技术问题),先**画出"谁在桌上、谁的力量多大、谁的利益冲突"**——再决定**优先级、联盟、规避动作**。
**适用阶段**:议题分析第 1.5 步(横向切面)→ 嵌入 PESTLE/波特五力/SWOT 全流程,**不替代它们,而是"补上人"的维度**——同样的外部环境,不同的利益相关方,战略完全不同。

**核心命题**:
> 政策/项目的成败 = **70% 在技术可行性,30% 在利益相关方博弈**——而 30% 经常是失败的主因。
> 真正的利益相关方分析 = 不只列"谁相关",而是**画出权力 × 利益 × 立场 × 关系网络**,识别**关键少数**与**隐性反对者**。
> 工具:不是"列表格",是"画地图"——把每个主体的位置(权力-利益矩阵)、相互关系(联盟-冲突)、动态变化(时间维度)可视化。

**与其他框架的层级关系**:
```
PESTLE          → 识别环境(无主体)
波特五力         → 识别行业结构(有竞争对手)
利益相关方分析    → 识别"人"(权力-利益-立场-关系)
   ↓
SWOT(对单主体) / 情景规划(对时间维度) 时,**必先做**利益相关方分析
否则再完美的 PESTLE/SWOT 也会被"人"推翻
```

## 2. 核心概念拆解

### 2.1 利益相关方的定义

**利益相关方(Stakeholder)** = 任何**能影响**决策、或**被决策影响**的个人/组织/群体。
**Freeman 原版定义**:能影响组织目标实现或受其影响的任何群体(广义)。
**实务切分**:不只股东、员工,还包括**监管、社区、媒体、上下游、潜在受影响公众、未来世代**。

### 2.2 四维属性(每个主体必填)

| 维度 | 核心问题 | 1-5 分定义 | 信息源 |
|------|----------|------------|--------|
| **权力(Power)** | 阻止/推动决策的能力多大? | 1=无 5=绝对否决权 | 资源/法律/舆论/资金/技术 |
| **利益(Interest)** | 与议题的利益相关度多强? | 1=无关 5=生死攸关 | 财务敞口/法律义务/价值观 |
| **立场(Position)** | 支持/反对/中立?程度? | -5(强烈反对)~+5(强烈支持) | 公开声明/历史投票/行动 |
| **关系(Relation)** | 与其他主体的联盟/冲突? | +1(同盟)~-1(对立) | 合作历史/共同声明/对抗记录 |

**关键原则**:
- **权力 ≠ 利益**:监管可能权力大但利益弱(只为合规),小供应商可能权力小但利益强(生死攸关)
- **立场 ≠ 关系**:利益相关方 A 与 B 立场相同,不一定联盟(可能有内部矛盾)
- **关系是网络属性,不是单个属性**——必须画出"主体 × 主体"关系矩阵

### 2.3 主体识别清单(8 类标准分类)

| # | 类别 | 典型主体 | 识别技巧 |
|---|------|----------|----------|
| 1 | **决策方** | 政府/股东/董事会/项目经理 | 谁有最终决定权? |
| 2 | **执行方** | 管理层/承包商/合作伙伴 | 谁来具体落地? |
| 3 | **监管方** | 行业监管/审计/纪检/反垄断 | 谁可以叫停? |
| 4 | **资金方** | 投资人/银行/出资人/纳税者 | 谁出钱? |
| 5 | **受影响方** | 员工/客户/社区/上下游 | 谁的利益被动? |
| 6 | **舆论方** | 媒体/KOL/智库/NGO/公众 | 谁在放大声音? |
| 7 | **隐性方** | 未来世代/生态/历史责任 | 虽不在场但必须代为发声 |
| 8 | **外部冲击方** | 竞争者/技术颠覆者/地缘/黑天鹅 | 不在桌上但能掀桌 |

**强制要求**:每个议题至少识别 **15-25 个主体**,覆盖 8 类。少于 15 个 = 一定有遗漏(尤其舆论方 + 隐性方)。

## 3. 分析步骤(标准 SOP)

### 步骤 1:议题界定 + 边界锁定
- 输入:1 句议题边界(例:"某市 2027 城区老旧小区改造 PPP 项目" / "某新能源车企 2026 海外建厂")
- 输出:**议题卡**:议题范围 / 时间窗 / 地域 / 利益敞口规模
- **关键原则**:锁边界(谁在范围内,谁不在)避免分析外溢

### 步骤 2:主体识别(8 类全覆盖)
对议题做**全主体扫描**,8 类各问"有没有?有几个?",产出**主体清单**。
- 每个主体标注:类别(8 类之一)、一句话身份(例:"市发改委城建处 · 处长 A")、一句话利益诉求
- **隐藏技巧**:问"如果这件事失败,谁最开心?"→ 找出隐性反对者
- **隐藏技巧**:问"如果这件事成功,谁最不开心?"→ 找出被边缘化群体
- 数量控制:**15-25 个主体**(少于 15 必有遗漏,多于 30 重点模糊)

### 步骤 3:四维打分(权力/利益/立场/关系)
对每个主体**逐个打分**:
- **权力**(1-5):资源 / 法律 / 舆论 / 资金 / 技术 5 维度哪个最强?综合给 1-5
- **利益**(1-5):财务敞口 / 法律义务 / 价值观 哪个最强?综合给 1-5
- **立场**(-5 ~ +5):公开声明 / 历史行动 / 利益推理 综合给分
- **关系**(+1/-1/0):与其他主体的历史关系(只看明确可证的关系)
- **信息源标注**:每个打分必须可追溯(财报/公告/采访/历史投票)

### 步骤 4:权力-利益矩阵(2x2 切分)
把每个主体放进**2x2 矩阵**:
```
       权力高
        |
  关键  |  关键
  玩家  |  玩家
  (低利益)| (高利益)
--------+--------
        |
  旁观  |  重要
  者    |  参与者
  (低利益)| (高利益)
        |
       权力低
        利益低 ← → 利益高
```

| 区域 | 策略 | 沟通频次 |
|------|------|----------|
| **高权力 + 高利益(关键玩家)** | 主动管理 · 共建方案 · 优先联盟 | 周/月 |
| **高权力 + 低利益(关键旁观)** | 定期汇报 · 维持关系 · 防止突然介入 | 季度 |
| **低权力 + 高利益(重要参与者)** | 充分知情 · 利益补偿 · 防止结盟反对 | 关键节点 |
| **低权力 + 低利益(旁观者)** | 监测动态 · 不主动投入 | 半年/年 |

### 步骤 5:关系网络图(联盟/冲突可视化)
画出**主体 × 主体**关系图(节点 + 边):
- **实线(蓝)**:明确联盟(合作历史/共同声明/共同利益)
- **虚线(红)**:明确冲突(对抗历史/相反利益/法律纠纷)
- **灰色**:无明确关系
- **节点大小**:权力值
- **节点颜色**:立场(绿=支持 / 黄=中立 / 红=反对)
- **产出**:**联盟-冲突子图**:谁和谁铁杆同盟?谁和谁不可调和?

**关键识别**:
- **铁三角**(3 个高权力主体联盟)= 几乎不可阻挡 → 必须成为其一员或分化
- **隐性联盟**(无明确声明但利益高度一致)= 未来最大风险 → 提前化解
- **摇摆者**(立场 0 附近)= 关键少数 → 重点争取

### 步骤 6:策略矩阵(7 类策略 × 主体清单)
对每个主体制定**沟通/管理策略**,7 类标准策略:

| 策略 | 适用 | 动作 |
|------|------|------|
| **P 合作(Partner)** | 高权力+高利益+立场正向 | 共建方案 · 利益共享 |
| **A 联盟(Alliance)** | 中权力+正向立场 | 议题结盟 · 联合发声 |
| **I 知情(Inform)** | 高权力+低利益 / 旁观者 | 定期汇报 · 不参与决策 |
| **C 咨询(Consult)** | 高利益+低权力 | 充分对话 · 利益补偿 |
| **D 防御(Defend)** | 高权力+反向立场 | 法律/技术/舆论对抗 |
| **M 监控(Monitor)** | 潜在风险方 | 持续监测 · 提前预警 |
| **N 不参与(Neutral)** | 利益+权力均低 | 资源允许时少量维护 |

**强制要求**:每个主体分配**唯一主策略** + **明确动作**(3 个月内可做)。

### 步骤 7:动态复盘(每季度 / 每个里程碑)
- 哪些主体权力/利益变了?(例:某投资人减持 → 权力 5→3)
- 哪些立场变了?(例:某媒体从支持→质疑)
- 新主体出现?(例:某 NGO 突然加入议题)
- 联盟/冲突重组?(例:两铁杆盟友因利益分歧分裂)
- **强制产出**:**Stakeholder Heatmap 更新版**,对比上个季度

## 5. 经典案例(3 个)

### 案例 1:某市老旧小区加装电梯 PPP 项目(政策推演型)
- **议题边界**:某市 2026-2028 老旧小区加装电梯 PPP 项目
- **关键发现**:
  - 主体清单 22 个(决策 3 / 执行 4 / 监管 3 / 资金 3 / 受影响 5 / 舆论 2 / 隐性 1 / 外部 1)
  - **铁三角**:市住建局 + 财政局 + 国资委(高权力+高利益+正向立场)
  - **隐性反对**:低层住户(利益高+权力低+立场-4),被联盟忽略后引发 6 次群体上访
  - **关键摇摆者**:本地电视台(权力 3 + 利益 2 + 立场 0),后被反向舆论推到 -3
- **策略纠错**:
  - 错误版:对低层住户只做"补偿通知" → 失败
  - 修正版:对低层住户(低权力+高利益+反向)做 **C 咨询**+**利益补偿方案**(免维护费/年补贴 3000 元)→ 立场从 -4 回升到 -1

### 案例 2:某新能源车企 2026 海外建厂选址(企业战略型)
- **议题边界**:东南亚建厂选址(越南/泰国/印尼 3 选 1)
- **关键发现**:
  - 主体清单 25 个(含地缘政治对手)
  - **关键玩家**:母公司董事会 + 东南亚三国政府 + 美国贸易代表办公室(USTR)
  - **隐性联盟**:美国 + 印尼(都希望"非中国"主导东南亚 EV)→ 中方在印尼建厂面临隐性阻力
  - **关键摇摆者**:泰国军政府(立场 +1 → -2 因大选变动)→ 推迟建厂 6 个月
- **策略纠错**:
  - 错误版:只对比三国补贴/税率 → 失败(忽略地缘)
  - 修正版:加 USTR + 东盟自贸区 + 美国 IRA 补贴 → 改为泰国 + 当地合资 + 美国 LPO 申请 → 落地

### 案例 3:某 AI 大模型 2026 商业化路径(技术战略型)
- **议题边界**:某大模型 2026 ToB vs ToC 商业化路径选择
- **关键发现**:
  - 主体清单 18 个
  - **铁三角(正向)**:CEO + CTO + 大客户(运营商/银行)
  - **铁三角(反向)**:3 家竞品 + 媒体质疑派 + 部分投资人(担心 ToC 烧钱)
  - **关键摇摆者**:监管(网信办/工信部) → 政策随时收紧
  - **隐性方**:开源社区(权力低+利益高+立场 +4),被忽略后发起"对抗闭源"运动
- **策略纠错**:
  - 错误版:重金砸 ToC + 不理开源 → 反向联盟扩大
  - 修正版:ToB 现金流 + ToC 限量发布 + 开源部分模型(社区立场 +4 维持)→ 监管立场 -2 回到 0

## 6. 与智库方法论骨架的衔接

### 6.1 横向(与其他框架)
- **PESTLE 之后必做**:PESTLE 告诉你"环境会怎样变",利益相关方告诉你"谁会推动/阻碍这个变化"
- **波特五力之后必做**:五力识别"行业结构",利益相关方识别"每种力量背后的人"
- **SWOT 之后必做**:SWOT 对单主体,利益相关方对"多主体博弈"
- **情景规划之后必做**:每个情景都有不同的"赢家-输家"= 不同的利益相关方格局

### 6.2 纵向(智库三层闭环)
```
PESTLE(宏观无主体) → 利益相关方(宏观带主体) → 波特五力(中观带结构) → SWOT(微观单主体) → 情景规划(时间维度)
```

利益相关方分析 = **PESTLE 与波特五力之间的"桥梁"**——PESTLE 是"宏观环境",利益相关方是"宏观中的人",然后到波特五力是"行业结构里的人"。

### 6.3 关键命题(智库方法论锚点)
- `_ThinkTankLib/02-政治`:政策推演 = 不同利益相关方博弈的演化
- `_ThinkTankLib/03-经济`:产业政策 = 政府+企业+公众三角关系
- `_ThinkTankLib/05-战略`:战略选择 = 在利益相关方约束下的最优解
- `_ThinkTankLib/07-社会`:社会议题 = 受影响方 + 舆论方 + 决策方的三方博弈
- `_ThinkTankLib/09-国际`:地缘议题 = 国家作为利益相关方的对抗与联盟

## 7. 常见陷阱(智库顾问必避)

1. **"只列内部,忽略外部"陷阱** → 决策方 + 执行方 ≠ 完整清单,**舆论方 + 隐性方 + 外部冲击方** 才是政策/项目失败主因
2. **"权力 = 利益"陷阱** → 监管可能权力 5 但利益 1(只为合规),小供应商权力 1 但利益 5(生死攸关) → 矩阵必须画 2 维
3. **"立场 = 关系"陷阱** → 两个主体立场都是反对,但可能因为不同原因不联盟(政策反对 vs 商业反对)
4. **"一次性分析"陷阱** → 利益相关方是**动态网络**,每季度必须复盘,新主体(新 NGO/新投资人)出现会颠覆格局
5. **"全员管理"陷阱** → 资源有限,**只重点管理 4-6 个关键玩家 + 1-2 个关键摇摆者**,其余做"监控"
6. **"中性就好"陷阱** → 利益相关方分析本身**就是政治动作**(画图/打分/贴标签),不要假装"客观"——明确策略选择
7. **"忽略隐性方"陷阱** → 未来世代/生态/历史责任虽不在场,但 ESG/政策合规/长期声誉必代为发声
8. **"沟通万能"陷阱** → 不是所有反对都能沟通解决,**结构性冲突**只能化解/规避/对抗,不要假装能"说服所有人"

---

## 8. 一句话总结

> **利益相关方分析 = 把"环境分析"变成"人"的地图**。
> 同样的 PESTLE 外部环境,不同的人格局,产生完全不同的战略。
> 智库顾问的功力不在"识别框架",而在"画出看不见的人"。
> 关键 3 步:**主体识别(8 类全覆盖 15-25 个) → 四维打分(权力/利益/立场/关系) → 策略矩阵(7 类主策略 + 3 个月内动作)**。
